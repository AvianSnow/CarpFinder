Living notes about how upstream Space Station 14 is structured. Expand as we learn more.

## Solution layout

| Project | Role |
|---|---|
| `Content.Shared` | Prototypes, components, net messages, shared systems (no UI) |
| `Content.Server` | Authoritative game logic |
| `Content.Client` | UI, prediction mirrors, client systems |
| `Content.Shared.Database` / `Content.Server.Database` | Persistence |
| `RobustToolbox/` | Engine (UI, ECS, networking, XAMLIL) — treat as upstream |
| `Resources/` | Prototypes YAML, locales (`.ftl`), textures, maps, audio |

Upstream remote: `https://github.com/space-wizards/space-station-14.git` (git remote `upstream`).

## ECS quick map

- **Entities** = ID + set of components.
- **Components** = data only (`[RegisterComponent]`, often `[NetworkedComponent]` + `[AutoGenerateComponentState]`).
- **Systems** = logic (`EntitySystem`, event handlers).
- Shared systems run on both sides when prediction/replication needs it; server-only for authoritative rules.

Prototypes (`IPrototype`, `[Prototype("kind")]`) are data-driven definitions loaded from `Resources/Prototypes/**/*.yml`.

## Melee sounds

Swing and hit audio are data on `MeleeWeaponComponent` (`soundSwing`, `soundHit`), played by `MeleeSoundSystem`. A miss plays the swing. A hit plays the hit sound, unless the target's `MeleeSoundComponent` has a sound for that damage group. Setting `MeleeHitEvent.Handled` returns before the hit sound, so a system that replaces damage has to play it.

## Late `MsgEntity`

`net.ent: Got late MsgEntity` is `net.log_late_msg` (on by default). It is a client **input** whose source tick is behind the server tick. The server still queues and applies it (`SourceTick <= CurTick`). It is not a dropped entity-state diff. `Diff -7` at 30 ticks/s is about 0.23s of server stall. `subTick` is a fraction of one tick, and `func` is a keybind id. A local server prints this when a tick runs long, then catches up. A dying body still slides in the physics step. That move does not schedule flanking. The dying recovery check runs once per game tick.

## Client UI

- Robust UI is XAML + code-behind (`*.xaml` / `*.xaml.cs`), similar to Avalonia.
- `[GenerateTypedNameReferences]` generates typed accessors for named XAML controls.
- `RobustXamlLoader.Load(this)` is replaced at build time by XamlIL with the precompiled populate method. If you see `No precompiled XAML found for …`, the XAML was not compiled onto that type (wrong `x:Class` / path, or stock XAML still colliding).
- `UIController` types (e.g. `LobbyUIController`) own lobby/setup windows. Many are `sealed`; prefer CF overlays over editing them.

## Lobby / character setup

Upstream lives under `Content.Client/Lobby/`:

- `LobbyState`, `LobbyUIController` — state + open/save character setup
- `UI/HumanoidProfileEditor.*` — character editor (partial class split across Appearance, Roles, Traits, …)
- `UI/CharacterSetupGui.*` — slot picker wrapping the profile editor
- `UI/Loadouts/`, `UI/Roles/`, `UI/ProfileEditorControls/` — supporting controls

`LobbyUIController.EnsureGui()` constructs `HumanoidProfileEditor` and nests it in `CharacterSetupGui`. Keeping that public API stable lets CF replace only the editor UI without touching the controller.

## Prototypes & locale

- YAML under `Resources/Prototypes/` (CF: `Resources/Prototypes/_CF/`).
- Fluent locale under `Resources/Locale/en-US/` (CF: `Resources/Locale/en-US/_CF/`).
- Loc keys referenced as `{Loc 'key'}` in XAML or `Loc.GetString("key")` in C#.

## Upstream sync hygiene

- Prefer zero diffs in stock `Content.*/` trees outside `_CF/`.
- Compare Lobby (and similar) against `upstream/master` when checking accidental hub edits.
- Project-file `Compile Remove` / `EmbeddedResource Remove` / `AdditionalFiles Remove` can swap a stock type for a `_CF` replacement without editing the stock file body.
